产品重复开品检测器

技能描述

本技能用于检测产品是否存在重复开品。支持输入 SKU、SPU、产品标题或产品图片，先通过相似标题/相似图片接口召回候选池，再基于候选代表 SKU 的销售信息进行重复判断。

触发场景

当用户要求查重、检测重复开品、检查产品是否已存在，或提供标题/图片/SKU/SPU 要求查找相似产品时，应调用本技能。

输入方式

SKU编码：PHK_3AP48K3C
SPU编码：PHK_3AP4
产品标题：儿童学习椅
产品图片：https://xxx.com/image.jpg
SKU列表：xxx, xxx
SPU列表：xxx, xxx

支持单个或多个目标，多个目标以列表形式输入。

目标数量超过 10 个时，先提示“本次共 N 个目标，检测耗时较长，建议分批进行以获得更完整的结果”，提示后仍按用户要求继续执行，不得拒绝或强制拆分。目标数量为 10 个及以下时，不输出该提示。

单个目标查询失败或状态异常，不影响其余目标继续执行。

多目标处理规则

输入为多个目标时，按以下规则处理：

  • 按输入顺序逐个目标独立执行步骤1~步骤6；
  • 排除集合按各自目标分别计算：查目标 A 时使用 A 的 spu_code 与 A 的 spu_relation_group，查目标 B 时使用 B 的，不合并；
  • 目标之间不互相排除：查目标 A 时，本次输入的其他目标仍可作为候选参与判断，用于发现本批产品之间的重复；
  • 结果按输入顺序输出；单个目标的失败或异常在汇总中标注，不中断其他目标。

执行步骤

步骤1：获取目标产品信息

输入为 SKU/SPU 时，先获取目标销售信息。

1.1 输入识别规则

  1. 明确输入 SKU：调用 get_developer_sales_info(sku_code) 获取该 SKU 的销售信息，并直接将该 SKU 作为目标代表 SKU。
  2. 明确输入 SPU：调用 get_developer_sales_info(spu_code) 获取该 SPU 下 SKU 列表，并从返回 SKU 中选择目标代表 SKU。
  3. 未标明 SKU/SPU 的编码，按以下顺序执行，不得跳过任何一步、不得提前终止：
    • 第一步：按 spu_code 查询；
    • 第二步：第一步无返回时，必须再按 sku_code 查询同一编码；
    • 第三步：两次均无返回，才可判定“无产品信息”。
    • 禁止：第一次查询为空即终止，或未执行第二步就判定编码不存在。
    • 长度仅作辅助参考，不可作为唯一判据：8 位（如 PHK_337D）优先按 SPU 查询；14 位及以上优先按 SKU 查询；11/12/13 位长度存在歧义，两种都必须查询。
  4. 输入标题或图片：不获取目标销售信息，直接进入相似搜索。仅输入标题或仅输入图片时，结果最多为“疑似重复”；同时输入标题和图片时，若标题主体一致且外形主体一致，结果最多可判定为“同款产品”，但因缺少系统SKU/SPU信息，不判定为“相同产品”。

1.2 目标代表 SKU 规则

  • 若输入为 SKU：直接使用输入 SKU 作为目标代表 SKU，不再根据所属 SPU 重新选择 SKU。
  • 若输入为 SPU：按以下规则选择目标代表 SKU：
    • 优先选择 sales_info.is_independent_saleable = 1 的 SKU；
    • 如果均不可独立售卖，选择第一个 SKU。
  • 后续标题搜索、图片搜索和重复判断，均基于目标代表 SKU。
  • 无论输入为 SKU 还是 SPU，完成本步骤后必须记录目标SPU编码（即步骤1 返回的 spu_code，也就是用户输入的那个产品自身的 SPU），供步骤3 排除自身使用。

  • 返回列表包含目标SPU本身；
  • 未返回该字段时，表示目标SPU不存在关联组。

步骤2：召回相似候选

基于步骤1获取到的目标代表 SKU 信息调用相似接口。

2.1 调用工具

目标代表 SKU 信息工具参数
sku_cn_title 非空similar_title_searchsearchWord = sku_cn_title
main_image_url 非空similar_image_searchurl = main_image_url

2.2 调用规则

  1. 输入为 SKU/SPU 时，必须先按步骤1获取目标代表 SKU。
  2. 输入为 SKU 时，直接使用该 SKU 的 sku_cn_title 和 main_image_url 进行召回，不得重新选择目标 SKU。
  3. 只要目标代表 SKU 有 sku_cn_title，就必须调用 similar_title_search。
  4. 只要目标代表 SKU 有 main_image_url，就必须调用 similar_image_search。
  5. 如果 sku_cn_title 和 main_image_url 都有，两个接口都必须调用。
  6. 只有在用户仅输入标题且无法获取目标 SKU 信息时，才只调用标题搜索。
  7. 只有在用户仅输入图片且无法获取目标 SKU 信息时，才只调用图片搜索。
  8. 相似接口只用于召回候选，不直接作为重复判断依据。

2.3 标题相似搜索规则

当目标代表 SKU 的 sku_cn_title 非空时，标题相似搜索按以下规则执行：

  1. 第一次搜索：使用完整 sku_cn_title 调用 similar_title_search。
  2. 若完整标题搜索无返回，或按步骤3过滤、步骤4筛选后无有效候选，才允许进行第二次搜索。
  3. 第二次搜索：使用标题主体词调用 similar_title_search。
  4. 标题搜索最多执行两次，不得自行拆分多个关键词反复搜索。
  5. 标题搜索命中只表示候选召回，不等于最终重复判断。

2.4 标题主体词提取规则

标题主体词优先基于结构化字段从 sku_cn_title 中扣减生成，不完全依赖模型自由理解。

生成规则：

  1. 以完整 sku_cn_title 作为原始标题。
  2. 从标题中去除 material 字段值。
  3. 从标题中去除 sku_attributes 中的变体属性值。
  4. 若 sku_attributes 中的值为英文，需结合常见中英文属性映射识别标题中的中文表达，例如：
    • Black = 黑色
    • Gray / Grey = 灰色
  5. 去除后保留核心产品对象、必要结构词、关键款式词、关键功能词。
  6. 不得只保留过宽泛的通用词。
  7. 不得将标题拆成多个词分别搜索。
  8. 若结构化字段不足，才按通用规则辅助去除颜色、尺寸、数量、包装方式、重量、型号、适配范围、套装数量、促销词等变体或规格信息。

示例：

目标信息：

{
  "sku_cn_title": "庭院红外线天花板取暖器-P05-GR15B碳纤维加热管 1500W  英规GARVEE 黑色 铝合金",
  "material": "铝合金",
  "sku_attributes": {
    "color": "Black"
  }
}

处理方式：

  • 去除材质：铝合金
  • 去除变体属性：Black 对应标题中的 黑色

标题主体词可提取为：

庭院红外线天花板取暖器-P05-GR15B碳纤维加热管 1500W 英规GARVEE

若品牌词会明显影响召回，也可进一步去除品牌词，得到：

庭院红外线天花板取暖器-P05-GR15B碳纤维加热管 1500W 英规

标题主体词仅用于完整标题搜索无返回，或按步骤3过滤、步骤4筛选后无有效候选时的兜底召回，不替代完整标题搜索。

2.5 图片相似搜索规则

  1. 当目标代表 SKU 的 main_image_url 非空时，必须调用 similar_image_search。
  2. 图片搜索命中只表示候选被召回，不直接等于外形一致。
  3. 不得仅根据图片 URL 不同判断外形不同。
  4. 是否外形一致，需在步骤6实际读取并比较目标图、候选图；图片搜索命中本身不能代替视觉判断。

2.6 候选合并规则

  1. 合并标题搜索和图片搜索返回的 data。
  2. 相同 spu 只保留一组。
  3. 同一候选 SPU 同时被标题和图片召回时，仅保留一组候选，并记录召回来源为“标题+图片”。
  4. 仅被标题召回的候选，召回来源记为“标题”。
  5. 仅被图片召回的候选，召回来源记为“图片”。
  6. 合并后的候选进入步骤3处理。

步骤3：过滤目标SPU及关联SPU

在进入候选销售信息查询和重复判断前，对候选SPU进行过滤。

  1. 排除SPU集合由以下内容组成：
    • 目标SPU：用户输入的那个产品自身的 SPU，即步骤1 get_developer_sales_info 返回的 spu_code 字段值。输入 SPU 时该值即输入的 SPU 编码；输入 SKU 时该值为该 SKU 所属的 SPU 编码（如 SKU PHK_337DHYKY 的 spu_code 为 PHK_337D）。该值在本次检测中唯一固定；候选产品的 spu_code、输入的原始编码本身、标题均不得作为目标SPU；
    • 目标销售信息返回的 spu_relation_group（如有）。
  2. 对排除SPU集合按SPU去重。
  3. 若召回候选中的 spu 命中排除SPU集合，则直接过滤，不进入后续筛选，也不再获取候选销售信息，不进入后续重复判断。候选 spu 与目标 spu_code 属同一编码体系，按字符串全等比较。

说明：

  • spu_relation_group 返回时已包含目标SPU本身；未返回时，仅过滤目标SPU（即上述 spu_code）；
  • 同一SPU及已维护关联关系的SPU均不作为重复开品结果；
  • 被过滤的候选不计入 candidate_count 和 non_duplicate_count；
  • 仅输入标题或图片、无法获取目标SPU信息时，不执行本步骤。

步骤4：候选产品筛选与代表 SKU 选择

相似接口返回的 data 中，每条数据代表一个候选 SPU；该条数据下的 spu_is_account_or_overdue 是该候选 SPU 下的 SKU 列表。

候选筛选按候选 SPU 维度执行。需要排除两类候选：一级品线为“服装”的产品，以及下列指定地毯品类。两类规则在此统一说明，但字段取得时间不同：地毯使用相似接口的 category_name_path，在本步骤过滤；服装使用候选销售信息中的 product_line_name，本步骤暂不判断，待步骤6取得详情后过滤。

对每个候选 SPU：

  1. 先使用 data[].category_name_path 过滤指定地毯品类。

若完整路径等于以下任一项，过滤该候选 SPU，不再处理其下 SKU：

  • 家居、厨具、家装>厨房和餐厅>餐厨布艺>厨房地毯>
  • 家居、厨具、家装>家居装饰>地毯、地垫和保护剂>地毯>
  • 艺术品、工艺品和缝纫用品>派对装饰品和用品>过道地毯>
  • 家居、厨具、家装>家居装饰>地毯、地垫和保护剂>儿童房地毯>
  • 家居、厨具、家装>家居装饰>地毯、地垫和保护剂>长条地毯>
  • 庭院、草坪和园艺>户外饰品>户外地毯>
  • 家居、厨具、家装>家居装饰>地毯、地垫和保护剂>无痕地毯贴和地垫>
  • 家居、厨具、家装>家居装饰>地毯、地垫和保护剂>地垫>
  1. 未被指定地毯品类过滤的候选 SPU，再处理其下 spu_is_account_or_overdue SKU 列表。
  2. 仅保留 product_lifecycle in [0, 1] 的 SKU。
  3. 若无符合条件的 SKU，过滤该候选 SPU。
  4. 在保留 SKU 中优先选择 packing_is_sale = 1 的 SKU。
  5. 如没有 packing_is_sale = 1，选择第一个保留 SKU。
  6. 每个候选 SPU 只保留一个代表 SKU。

说明：

  • 指定地毯品类按相似接口返回的 data[].category_name_path 原值判断。
  • 被指定地毯品类过滤的候选 SPU 不进入候选组，不参与后续重复判断，不输出详细结果。
  • 未命中指定地毯品类过滤规则时，才继续进行 SKU 状态过滤和代表 SKU 选择。

候选组结果：

  • 候选 SPU：data[].spu
  • 候选品类：data[].category_name_path
  • 代表 SKU：选中的 spu_is_account_or_overdue[].sku

步骤5：获取候选销售信息

对保留的每个候选组，使用代表 SKU 调用：

get_developer_sales_info(sku_code = 代表SKU)

获取候选代表 SKU 的销售信息，判断字段与步骤1目标产品字段一致，包括SKU、SPU、品类、品线、标题、主图、尺寸、重量、材质、变体属性、功能、采购价、供应商编码、是否可独立售卖等。

本步骤只负责获取销售信息，不做任何过滤；品线与配件的过滤统一在步骤6执行。

步骤6：执行重复判断

对目标代表 SKU 与候选代表 SKU 的销售信息进行判断。

判断顺序：

  1. 先对候选代表 SKU 做配件过滤与品线过滤；
  2. 再判断标题主体和外形主体是否一致；
  3. 标题主体一致且外形主体一致时，再根据采购价/供应商、关键规格字段区分“相同产品”或“同款产品”。

6.1 配件过滤

若候选代表 SKU 的 sku_attributes.specifications 命中配件标识，则不进入重复产品判断。

配件标识包括：

  • 配件
  • Accessory

支持带数字后缀，例如 配件1、配件2、Accessory 1、Accessory 2。 判断时忽略大小写和空格。

若 sku_attributes.specifications 为空或未命中配件标识，则继续执行重复判断。

被配件过滤的候选不进入最终重复判断，不计入 candidate_count，也不计入 non_duplicate_count。

6.2 品线过滤

读取候选代表 SKU 的 product_line_name 第一段（以 > 分隔，去除首尾空格）：等于“服装”则过滤该候选 SPU，不进入重复判断。

  • 字段缺失时不凭品类猜测为服装。
  • 被品线过滤的候选不计入 candidate_count，也不计入 non_duplicate_count。

6.3 标题和外形判断口径

  • 标题主体一致：核心产品对象、用途、结构/功能一致；SKU 标题中的颜色、尺寸、型号、适配范围、数量、套装规格等变体差异，不直接否定标题主体一致。
  • 外形主体一致：基于实际读取的目标图与候选图内容判断，产品主体结构、形态、部件组成、安装/连接方式一致；颜色、尺寸大小、局部配件数量差异，不直接否定外形主体一致。
  • 对每个候选，优先用当前模型可用的视觉能力读取目标图（目标代表 SKU 的 main_image_url，或用户直接提供的图片）与候选代表 SKU 的 main_image_url 对应图片；无法取得有效视觉结果时，调用 multimodal_understanding 分析两张图，再比较主体结构。仅返回 URL 或相似分数不算已分析图片。
  • similar_image_search 命中只表示候选被召回，不等于外形主体一致；不得仅凭接口命中或相似分数判定外形一致。
  • main_image_url 相同，可直接判定主图一致，不再调用视觉能力或 multimodal_understanding（同一地址指向同一张图片，主图内容必然一致）；main_image_url 不同，不能作为外形不同的依据，仍须实际读取并比较两张图的内容后才能判断。
  • 若任一主图缺失，或模型视觉及多模态工具均无法读取有效图片内容，则外形主体记为“无法确认”，并说明原因，不得声称已看图。
  • 仅输入图片时，无法获取目标标题，标题主体记为“无法比较”，判断结果最多为“疑似重复”，不判为“相同产品”或“同款产品”。
  • 输出判断依据（报告“判断依据”列与结构化 reason）时，先点明标题与外形各自的一致性结论，再写具体原因，不要只罗列现象。例：标题主体一致（核心产品均为儿童秋千，单座与双座为数量差异），外形主体一致（A型框架、橙蓝配色一致），但采购价不一致（274 vs 292），判定为同款产品。

6.4 采购价、供应商和关键规格判断口径

标题主体一致且外形主体一致时，再判断以下两组条件：

条件组A：采购价和供应商一致

  • supplier_code 一致；
  • purchase_price 整数部分一致。

purchase_price 判断时忽略小数部分，只比较整数部分，例如：

  • 268 与 268.00 视为一致；
  • 268.1 与 268.9 视为一致；
  • 268.9 与 269.1 视为不一致。

条件组B：关键规格字段基本一致

关键规格字段包括：

  • 尺寸：length / width / height
  • 重量：weight
  • 材质：material
  • 功能：sales_info.sell_points.功能

尺寸、重量可按 ±5% 容差判断；材质、功能按字段内容是否基本一致判断。

6.5 重复判断规则

条件结果说明
标题主体一致 + 外形主体一致 + 供应商编码一致 + 采购价整数部分一致相同产品供应商和采购价一致，基本可认为是同一产品
标题主体一致 + 外形主体一致 + 尺寸/重量/材质/功能基本一致相同产品关键规格字段基本一致，基本可认为是同一产品
标题主体一致 + 外形主体一致，但供应商/采购价、尺寸/重量/材质/功能均未达到相同产品判断标准同款产品标题和外形一致，但未满足相同产品条件，按同款产品处理
标题主体一致 + 外形主体不一致疑似重复标题主体一致，但外形不一致，需人工复核
标题主体一致 + 外形主体无法确认疑似重复标题主体一致，但图片不足以确认外形，需人工复核
标题主体不一致 + 外形主体一致疑似重复外形主体一致，但标题主体不一致，需人工复核
标题主体不一致 + 外形主体不一致非重复标题和外形均不同
标题主体不一致 + 外形主体无法确认非重复标题主体不一致，且图片无法提供有效相似依据
标题主体无法比较 + 外形主体一致疑似重复仅输入图片时，标题无法参与判断，最多判为疑似重复，需人工复核
标题主体无法比较 + 外形主体不一致非重复仅输入图片，且外形主体不一致
标题主体无法比较 + 外形主体无法确认非重复仅输入图片，且外形无法确认，无有效相似依据

说明：

  • “相同产品”和“同款产品”必须同时满足标题主体一致、外形主体一致。
  • 采购价/供应商、尺寸/重量/材质/功能只用于在标题主体一致、外形主体一致后，区分“相同产品”和“同款产品”。
  • 只满足标题主体一致，或只满足外形主体一致，均判为疑似重复。
  • 标题主体不一致，且外形主体不一致或无法确认时，判为非重复。
  • 输出判断结果时，应说明本次判断的关键依据；若判为同款产品，需说明未判为相同产品的主要差异。
  • 不得在 summary、reason、difference 中输出“条件组A”“条件组B”等内部规则编号，应直接写明具体判断依据。
  • 结构化输出中，判断依据写入 reason；同款产品的主要差异写入 difference。
  • 存在“相同产品”或“同款产品”即表示存在重复开品。

异常处理

单路异常不中断任务，按下表处理；处理完成后在 error_message 中按“记录”列填写。

异常处理error_message 记录

记录规则：

  • 多个原因同时出现时用 ； 连接，总长度不超过 60 字；
  • 除上表“记录”列给出的内容外，不得自行编写其他文案，不得粘贴接口报错原文；
  • 未出现上表任一异常时，error_message 为空字符串；
  • 候选级问题（召回来源、单张图不可读）由 recall_source、image_summary、image_analysis_source 记录，不在 error_message 中重复描述。

  2. 图片搜索命中不等于外形一致。

  5. 最终判断必须使用 get_developer_sales_info 返回的销售信息；涉及外形一致时，需实际读取目标产品与候选产品主图，图片相似接口的命中只表示候选被召回。
  6. 尺寸、重量可按 ±5% 容差判断。
  7. 本技能不负责批量跑数、断点续跑、Excel 落表。
  8. 编码查询必须先按 SPU、再按 SKU 各查询一次，两次均无返回才可判定“无产品信息”。
  9. 排除自身一律按步骤1 返回的 spu_code 执行：输入 SPU 时排除该 SPU，输入 SKU 时排除该 SKU 所属的 SPU；不得用 SKU 编码、标题或主图去判断自身。

输出语言

使用与用户输入相同的语言输出。

结构化输出要求

当调用方要求返回 JSON / JsonSchema / 结构化结果时，本技能不得输出自然语言检测报告，必须将检测结果整理为结构化 JSON。

结构化输出优先级高于默认报告模板。

顶层结构统一为 JSON 数组：无论单个还是多个目标，均返回数组，数组元素为下述字段构成的对象，顺序与输入顺序一致。单个目标返回长度为 1 的数组。

结构化输出字段包括：

  • target_sku：目标SKU
  • target_spu：目标SPU
  • target_title：目标SKU标题
  • target_category：目标品类路径
  • target_image：目标主图
  • status：处理状态，取值为“已完成 / 无产品信息 / 查询失败”
    • “无产品信息”仅指输入了 SKU/SPU 编码、且按 SPU 与 SKU 两种方式各查询一次均无返回数据的情形；只查询一种方式即判定无产品信息属于错误。仅输入标题或图片时，status 记为“已完成”。
  • is_duplicate：是否存在重复开品，取值为“是 / 疑似 / 否 / 空字符串”
  • same_product_count：相同产品数量
  • same_style_count：同款产品数量
  • suspected_count：疑似重复数量
  • non_duplicate_count：非重复候选数量
  • non_duplicate_spus：非重复候选的 SPU 编码数组，按 SPU 去重；只记编码，不记 SKU、标题、主图
  • candidate_count：参与最终判断的候选数量
  • summary：整体判断摘要
  • duplicate_items_json：重复明细 JSON 数组字符串
  • error_message：异常原因，取值见「异常处理」章节；无异常时为空字符串

duplicate_items_json 只包含以下三类明细：

  • 相同产品
  • 同款产品
  • 疑似重复

不得将“非重复”写入 duplicate_items_json。

duplicate_items_json 中每个对象包含：

  • duplicate_type：重复类型
  • similar_spu：相似SPU
  • similar_sku：相似SKU
  • similar_title：相似产品标题
  • similar_category：相似品类
  • similar_image：相似主图
  • recall_source：召回来源，标题 / 图片 / 标题+图片
  • title_judgement：标题主体一致 / 标题主体不一致 / 标题主体无法比较
  • image_judgement：外形主体一致 / 外形主体不一致 / 外形主体无法确认
  • image_summary：实际读取目标图与候选图后的主体结构比较依据；无法读取时注明原因，不得臆造图片内容
  • image_analysis_source：外形判断实际使用的读图方式，取值为“模型视觉 / 多模态 / 主图地址相同 / 未读图”
    • 模型视觉：用当前模型的视觉能力直接读取目标图与候选图后判断
    • 多模态：模型视觉未取得有效结果，改调 multimodal_understanding 后判断
    • 主图地址相同：目标与候选 main_image_url 完全相同，按步骤6.3 直接判定主图一致，未读图
    • 未读图：模型视觉与 multimodal_understanding 均无法读取有效内容，此时 image_judgement 必须为“外形主体无法确认”
  • reason：判断依据
  • difference：差异点
  • suggestion：建议处理

若无相同产品、同款产品、疑似重复，duplicate_items_json 返回 "[]"。 若无非重复候选，non_duplicate_spus 返回 "[]"。 duplicate_items_json 中 difference 字段，同款产品需填写主要差异，相同产品和疑似重复为空字符串。

计数字段要求：

  • same_product_count = duplicate_items_json 中 duplicate_type 为“相同产品”的数量
  • same_style_count = duplicate_items_json 中 duplicate_type 为“同款产品”的数量
  • suspected_count = duplicate_items_json 中 duplicate_type 为“疑似重复”的数量
  • candidate_count = 相同产品数 + 同款产品数 + 疑似重复数 + 非重复数
  • candidate_count 只统计进入最终重复判断的候选，不包含被指定地毯品类、服装品线、生命周期、目标SPU/关联SPU或候选配件规则过滤的候选。
  • non_duplicate_count = non_duplicate_spus 的数组长度（候选按 SPU 去重，一个候选对应一个 SPU）
  • image_judgement 为“外形主体一致”或“外形主体不一致”时，image_analysis_source 不得为“未读图”；出现该组合说明未实际读图即下了外形结论，该候选不得计入三类明细，须重新读取图片后再判断

error_message 规则：

只记录任务级异常，取值与写法按「异常处理」章节执行，不得自行编写其他文案。候选级的召回来源见 recall_source，图片读取情况见 image_summary 与 image_analysis_source，均不在本字段重复。未出现异常时返回空字符串。

is_duplicate 规则：

  • same_product_count > 0 或 same_style_count > 0：返回“是”
  • same_product_count = 0 且 same_style_count = 0 且 suspected_count > 0：返回“疑似”
  • 三类数量均为 0：返回“否”
  • status 为“无产品信息”或“查询失败”：返回空字符串

status 为“无产品信息”或“查询失败”时的字段取值：

目标信息未能取得时，召回与判断均不执行，不存在任何候选，不得编造候选或计数。除 target_spu、target_sku、status、error_message 外，其余字段一律按下表返回：

字段取值
target_title / target_category / target_image能取到则填，取不到返回空字符串
is_duplicate空字符串
same_product_count / same_style_count / suspected_count0
non_duplicate_count / candidate_count0
non_duplicate_spus[]
summary空字符串
duplicate_items_json"[]"

其中“查询失败”（含 SKU信息查询失败）表示目标信息从一开始就没取到，任务在该目标处直接终止，不执行步骤2 及之后的任何步骤；“无产品信息”表示接口正常但确实没有该产品，error_message 返回空字符串。
